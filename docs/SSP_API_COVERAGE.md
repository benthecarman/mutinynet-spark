# SSP API coverage

The SSP accepts GraphQL requests at `/graphql/spark/rc`,
`/graphql/spark/2025-03-19`, and `/graphql`. Financial mutations and
owner-scoped reads require a valid bearer session. Challenge handlers, fee
estimate handlers, and inert webhook compatibility handlers are public.

The server accepts the aliases and compressed request bodies generated by the
Spark JavaScript SDK. This table states the current behavior. A
compatibility-only operation returns the expected response shape but does not
complete the underlying financial action.

| Operation | Status | Current behavior |
|---|---|---|
| `get_challenge`, `verify_challenge` | Supported | Single-use five-minute challenge and durable 24-hour session |
| `leaves_swap_fee_estimate` | Supported | Returns `SSP_SWAP_FEE_SATS` |
| `request_swap` | Supported and tested | Verifies the funded outbound transfer and completes an atomic Swap V3 counter transfer from exact SSP leaves |
| `request_lightning_send` | BOLT11 supported and tested | Verifies Spark funding, starts one payment, tracks final LDK state, and settles the preimage swap idempotently |
| `lightning_send_fee_estimate` | Limited | Returns the current zero-fee policy; it is not a route estimate |
| `mint_invoice_preimage` | Supported SSP extension | Creates and stores an SSP-owned preimage before invoice creation |
| `request_lightning_receive` | Supported and tested for SSP-owned preimages | Creates a BOLT11 hold invoice, stores FROST shares, pays Spark before claim, and reconciles missed events |
| `reveal_preimage` | Supported SSP extension | Validates and reveals a wallet-held preimage for a matching receive request |
| `transfers`, `user_request` | Supported for SSP-created records | Returns owner-scoped durable swap and Lightning state |
| `lightning_receive_quote` | Compatibility only | Returns a signed JSON manifest; the SDK quote flow requires a protobuf `TransferManifest` |
| `static_deposit_quote`, `claim_static_deposit` | Regtest test path | Signs a fixed-value test quote; no production UTXO valuation or completed claim transfer |
| Instant static-deposit operations | Compatibility only | Stores or returns placeholder state |
| Cooperative-exit operations and fee quotes | Compatibility only | Returns static fees and stored state; no PSBT construction or on-chain send |
| `FetchCurrentUserToUserRequestsConnection` | Compatibility only | Returns an empty connection |
| Wallet webhook operations | Compatibility only | Returns empty or synthetic results; no delivery queue exists |

## Tested Lightning receive flow

The current end-to-end flow is:

1. Authenticate the wallet with the SSP.
2. Call `mint_invoice_preimage` through the authenticated SSP client.
3. Pass the returned hash to the SDK `createLightningHodlInvoice` method.
4. Pay the BOLT11 invoice.
5. Poll the receive request until `TRANSFER_COMPLETED`.

This flow lets the SSP fund the Spark transfer before it releases the
Lightning preimage. Ordinary quoted receive invoices are not supported until
the SSP emits the required protobuf manifest.

## SDK compatibility

MutinyNet uses `SIGNET` on the wire. The pinned JavaScript SDK fork maps SIGNET
correctly and treats TESTNET and SIGNET BOLT11 invoices as compatible because
both use the `lntb` prefix. Released SDK versions without that fix cannot run
the complete MutinyNet Lightning test.

BOLT12 sends are not production-supported. The SSP rejects offers in its
BOLT11-only funding verification and does not map BOLT12 payment state into
Spark settlement. `ldk-server` already exposes the send call, hash, and
preimage needed for SSP-side support.

See [ldk-server compatibility](LDK_GAPS.md) for the complete backend boundary.
